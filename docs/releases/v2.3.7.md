# Camaleon v2.3.7 — Settings S6 Risk mode

**Date:** 2026-06-11  
**Branch:** `dev`  
**Tag:** `v2.3.7`  
**Engine:** 1.6.0 (unchanged)

## Summary

**2.3.7** ships **Advanced / Risk mode** (Settings S6): an opt-in global flag that removes Camaleon's pixel, file-size, and consent limits for informed users on capable hardware. Browser and device limits still apply. SVG security checks are never bypassed.

## Highlights

- **Settings → Advanced / Risk** — acknowledge risks, then enable Risk mode (persisted in localStorage).
- **Limit pipeline** — 40 MP pixel block, elevated-byte consent, 12K astro preset gate, and SVG output-scale block bypass when Risk is on; hard byte cap raised to **500 MB desktop / 250 MB mobile**.
- **Wasm sync** — `set_risk_mode` exported on all transmutation crates; worker and prepare paths sync the flag per request.
- **Workspace banner** — visible while Risk mode is active; `LimitUnlockHint` hidden when limits are already removed.

## Technical

- `core_utils::set_risk_mode` / `risk_mode_enabled()` — skip `MAX_PIXELS` in validate when active.
- `transmutador_svg::svg_validate` — skip output W×H cap when Risk on.
- Frontend: `RiskModeProvider`, `computeLimitContext({ riskModeEnabled })`, `AstroResizePanel` 12K unlock, unit tests in `limit-context.test.ts`.
- Analysis: `docs/planning/risk_mode_analysis.md` (implemented).

## Not in this release

- **Settings S5** offline toolkit — deferred to next planning cycle.
