# Camaleon v3.0.1 — Offline mode polish (PWA follow-up)

**Date:** 2026-06-11  
**Branch:** `dev`  
**Tag:** `v3.0.1`  
**Engine:** 1.6.0 (unchanged)

## Summary

**3.0.1** refines the **v3.0.0** PWA offline shell with production-validated behaviour, honest **Offline mode** UX, and connectivity polish. Builds on Serwist + Settings S5 without engine changes.

## Features

- **Offline mode** — voluntary cache-only mode in Settings S5 (renamed from “offline simulation”); blocks same-origin network fetches while Wi‑Fi may stay on; tab-scoped via `sessionStorage`.
- **Dual cache-only enforcement** — `network-guard.ts` (fetch patch + bootstrap script) + Service Worker `SET_FORCE_OFFLINE` handler.
- **Offline & cache settings UX** — hero status, engine coverage stats, progress bar, offline checklist (production / `preview:cf` QA steps).
- **Connectivity UX** — minimal header pip; floating `OfflineStatusNotice` replaces invasive banner; server reachability probe when origin stops (e.g. localhost preview off).
- **Uncached engine guard** — `load-glue.ts` refuses uncached Wasm when Offline mode is active.

## Fixes / cleanup

- Removed obsolete `progress-preference.ts` facade (prepare progress lives in S4 notices prefs).
- i18n EN/ES aligned with production behaviour (no false “works in dev” claims).
- `force_offline_mode_notes.md` documents architecture and QA matrix.

## QA validated

- `npm run preview:cf` → online visit + S5 full download → stop server → app reloads and transmutations work offline.
- Incognito / first visit without cache correctly requires network.
