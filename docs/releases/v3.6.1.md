# Camaleon v3.6.1 — UpdateEngine refactor & message hierarchy

**Date:** 2026-06-22
**Branch:** `dev`
**Tag:** `v3.6.1`
**Engine:** 1.6.0 (unchanged)

## Summary

Maintenance release refactoring the **App Updates system** into a centralized `UpdateEngine`, reducing polling interval, fixing the "Reset welcome message" button to show onboarding immediately, and establishing a **message hierarchy** for new users — no more overlapping modals/toasts on first visit.

## Highlights

### Centralized UpdateEngine

- New `lib/app-update/update-engine.ts` — single source of truth for all update detection logic.
- State machine: `idle → checking → available → applying`.
- Service Worker detection (primary) + version beacon (secondary) coordinated in one module.
- Polling interval reduced from **5 minutes to 2 minutes**.
- Built-in visibility change + online event triggers.
- SW update subscription integrated directly into the engine.
- `AppUpdateProvider` simplified from ~270 lines to ~50 lines (thin wrapper).

### Message hierarchy for new users

- **LegalRefreshNotice removed** — the v3.4.0 legal policy refresh modal has been retired. New users already see current policies.
- **ReleaseNotesModal deferred** — changelog no longer appears in the same session as onboarding. Waits until the next visit.
- **OfflineInstallPromoNotice deferred** — hidden while onboarding is active. Also hidden when the changelog modal is pending (first visit), to avoid overlapping modals on mobile.
- **2-second fade-in animation** for OfflineInstallPromoNotice via CSS keyframe (`translateY` + `opacity`).

### Onboarding UX

- "Show again" button in Settings → Updates now closes Settings and shows the onboarding panel immediately — same fluid UX as "View What's New".
- New `openOnboarding()` function in `ReleaseCommsProvider`.
