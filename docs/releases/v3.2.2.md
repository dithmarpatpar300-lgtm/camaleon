# Camaleon v3.2.2 — Batch UX polish

**Date:** 2026-06-11  
**Branch:** `dev`  
**Tag:** `v3.2.2` (when promoted)  
**Engine:** 1.6.0 (unchanged from 3.2.1)

## Summary

Fixes batch UI/UX friction: **inline prepare** in the file list (no full-screen gate), **encode-only** re-runs when changing compression/quality on raster routes, and clearer hints for validated vs current settings.

## Changes

### Inline prepare (P0)

- **First drop:** full-screen `FilePrepareGate` while files are read and validated (same class as single-file).
- **After that:** workspace stays visible — Convert again, slider changes, and inline re-prepare use the file list only.

### Slider ≠ re-prepare (P2)

- On all 14 Tier 3.6.0 raster batch routes, changing compression/quality does **not** re-read files.
- `preparedOptions` snapshot captured when prepare finishes; hints show validated vs current values.

### Convert again (P1)

- **Download again** when cache matches last run options (unchanged).
- **Convert again** re-encodes selected Done rows in place — no spinner screen, no full re-prepare.
- `bytes` / `prepared` kept after Done until **Cancel batch**.

## QA exit gate

1. `npm run dev`
2. Drop 3+ JPEGs on JPG → PNG → list visible immediately; rows progress to Ready inline.
3. Change compression slider → hint updates; Transmute succeeds without re-prepare.
4. Complete batch → change slider → **Convert again** re-encodes without full-screen gate.
5. Same options as last run → **Download again** when cache hit.

## Not in this release

- GIF/TIFF/ICO batch (3.6.2+) — will use prepare-affecting options
- Universal multi-drop (3.6.1), ZIP export (3.6.2)
