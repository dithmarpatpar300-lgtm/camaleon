# Camaleon v3.5.2 — Risk Mode decoder fix & batch UX hardening

**Date:** 2026-06-20
**Branch:** `dev`
**Tag:** `v3.5.2`
**Engine:** 1.6.0 (unchanged)

## Summary

Hardening release fixing **Risk Mode memory limits being ignored during image decode** across all transmutator crates, plus **batch state management corrections** for error items, download buttons, and file size display during prepare.

## Highlights

### Risk Mode decoder memory limit bypass (all crates)

- **Symptom:** Files of 200 MP with Risk Mode enabled still failed with `"Failed to decode JPEG: Memory limit exceeded"`.
- **Root cause:** The `image` crate v0.25 applies `Limits::default()` with `max_alloc: 512 MB` during `ImageReader::decode()`. Camaleon correctly set `set_risk_mode(true)` in `core_utils` (bypassing the 40 MP pixel cap), but never configured the decoder's internal allocation limits. A 200 MP JPEG requires ~600 MB decoded raster, exceeding the 512 MB default.
- **Fix:** In all 8 crates using `ImageReader::decode()`, added `reader.no_limits()` when `core_utils::risk_mode_enabled()` before calling `.decode()`. Crates fixed: `transmutador_encode`, `transmutador_jpg`, `transmutador_optimize`, `transmutador_png`, `transmutador_webp`, `transmutador_bmp`, `transmutador_avif_encode`, `transmutador_ico`.
- **Not affected:** `transmutador_gif`, `transmutador_tiff`, `transmutador_tga` (use custom decoders, not `ImageReader`); `transmutador_avif` (uses `zenavif`); `transmutador_svg` (uses `resvg`).

### Batch error items auto-deselect + checkbox disabled

- Error-state items now auto-deslect (`selected: false`) and have their checkbox disabled.
- Error items removed from `isTransmutableStatus` — they no longer count toward `readyCount` or `transmutableSelectedCount`.
- `handleSelectAll` no longer selects error or blocked items.

### Batch download button for done items in mixed state

- When not all files are done (e.g. 3 done + 2 error), a new **"Download Again {x}"** button appears for selected done items, enabling re-download without requiring all files to be complete.
- Reuses existing `onConvertAgain` callback and i18n keys.

### File size preservation across Universal handoff

- `FileHandoffPayload` now carries `originalSize: number` — the exact file size from disk at drop time.
- Reconstructed `File` objects register their original size via a `WeakMap<File, number>`.
- `BatchItem` gains `displaySize` field, populated from the original size (handoff path) or `file.size` (direct drop path).
- `BatchFileRow` uses `item.displaySize` for the details line, ensuring accurate display regardless of path.

### Prepare progress shows correct per-file size

- `BatchPrepareProgress` now includes `fileSize: number`.
- `FilePrepareGate` during batch prepare now shows the size of the file currently being processed, not always the first file in the batch.

## QA exit gate

1. **Risk Mode + large files:** Enable Risk Mode (Settings S6), drop a 200 MP JPEG on JPEG→WebP → transmutes successfully.
2. **Batch error items:** Process a mix of valid + corrupt files → error items auto-unselected, checkbox disabled, not counted in download buttons.
3. **Batch done re-download:** 3 files done + 2 error → select the 3 done files → "Download Again 3" button appears and works.
4. **Prepare progress sizes:** Drop 9 files → each file shows its own correct disk size as the prepare queue advances.
5. **`cargo test --workspace`** passes (SVG `text_latin_meta_and_render` pre-existing failure).
6. **`npm test`** — 183 Vitest tests pass.
