# Camaleon v3.2.3 — Multi-file batch polish

**Date:** 2026-06-11  
**Branch:** `dev`  
**Tag:** `v3.2.3` (when promoted)  
**Engine:** 1.6.0 (unchanged from 3.2.1)

## Summary

Polishes **multi-file batch** on dedicated tool routes: initial prepare gate, encode-only re-runs, cache redownload, option hints, and Transmute button state sync.

## Shipped (internal: Tier 3.6.0 exit gate)

- Multi-drop on **14 raster tool routes** (allowlist)
- Shared options, per-row selection, sequential prepare → transmute
- One download per file; strict format gate (incompatible files skipped)
- Single-file path unchanged when one file is dropped

## Changes since v3.2.1

### Batch UX (v3.2.2 scope)

- **First drop:** full-screen `FilePrepareGate` (same class as single-file)
- **After first prepare:** workspace stays visible; Convert again / slider changes use inline list progress only
- **Encode-only** on raster routes: compression/quality changes do not re-read files
- `preparedOptions` snapshot + hints (validated vs current settings)
- **Download again** when worker cache matches last run; **Convert again** re-encodes in place
- `bytes` / `prepared` kept after Done until Cancel batch

### Bug fixes (v3.2.3)

- **`commitItems` sync:** UI state and `itemsRef` stay aligned — Transmute no longer fails while rows show Ready
- **Batch vs single-file prepare:** initial gate only on first upload; subsequent ops never hijack the screen

## QA exit gate

1. `npm run dev`
2. Drop 3+ camera JPEGs on JPG → PNG → gate on first load → all Ready → **Transmute 3** succeeds
3. Complete batch → change slider → **Convert again** without full-screen gate
4. Same options as last run → **Download again** when cache hit
5. Single-file route unchanged (one file → `TransmutationPanel` + gate as before)

## Not in this release (Tier 3.6.1+)

- ZIP export (3.6.2)
- GIF / TIFF / ICO / SVG batch with per-row options (3.6.2+)
