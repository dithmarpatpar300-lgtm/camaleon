# Camaleon v3.5.1 — Batch drag-drop fix & download format UX

**Date:** 2026-06-19  
**Branch:** `dev` → `main`  
**Tag:** `v3.5.1`  
**Engine:** 1.6.0 (unchanged)

## Summary

Patch release fixing **multi-file drag-and-drop on dedicated transmutator routes** (e.g. PNG→JPEG) when files are dragged from Windows Explorer, plus **batch download format guidance** in the batch workspace with a Settings deep link to the download preference row.

## Highlights

### Multi-file drop on tool routes (fix)

- **Symptom:** Dragging 5 files onto `/transmute/png-to-jpg` loaded only 1 file; the file picker with the same selection worked.
- **Root cause:** `usePageFileDrop` (window listener) and the tool `Dropzone` both handled the same drop; `PageDropOverlay` intercepted pointer events during page-level drag feedback.
- **Fix:** `stopPropagation()` on tool dropzone drag/drop (aligned with Universal transmutator); overlay is **visual-only** (`pointer-events-none`); window handler skips drops on `.transmute-dropzone`; `getDroppedFiles()` reads `dataTransfer.items` for Explorer multi-select.

### Batch download format UX

- **Contextual tip** in batch workspace when 2+ files: suggests ZIP when preference is individual (and vice versa).
- **Settings deep link** `openSettings({ focus: "batch-download" })` scrolls to Batch & universal and pulses **only** the download format row (`settings-row-batch-download`).
- **Mode-aware hints** — validation and “all done” copy differ for individual vs ZIP; cached ZIP download uses stored outputs without re-encode.
