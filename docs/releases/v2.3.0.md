# Camaleon v2.3.0 — Operational Notice Rail

**Date:** 2026-06-11  
**Tag:** `v2.3.0` (pending merge to `main`)  
**Wave:** UX infrastructure — contextual guidance for all 19 tools

## Summary

Camaleon **2.3.0** ships the **Operational Notice Rail** — a centralized, adaptive context system that helps users understand **when conversion or estimation may take longer**, when **limits apply**, and when **format-specific caveats** matter. Applies to **every active transmutation tool**, not only AVIF encode.

**Tags:** **NEW** (Notice Rail UX) · **PERFORMANCE** (clearer expectations during heavy encode/estimate paths)

## Categories

| Tag | Scope |
|-----|--------|
| **NEW** | `NoticeRail` + `NoticePanel`; per-tool latency profiles; limit/fidelity/performance resolvers |
| **PERFORMANCE** | Adaptive L0–L3 cost tiers; slow-estimate copy after 3s; `cacheReadySlow`; transmute gate hints |
| **CLEANUP** | Removed legacy `OutputSizeNotice`, `BmpPngGrowthNotice`, `LargeFileNotice`, `TransmutationDropzone` |

## User-facing

- **Context rail** in the staged panel (between options and size metrics) — up to **2** prioritized notices
- **Honest slow-path warnings** for AVIF encode, heavy GIF/TIFF frames, large megapixel files, elevated byte zones
- **Estimate feedback** when calculation runs longer than a few seconds
- **“Ready — conversion may take a while”** when settings imply a heavy transmute
- **Transmute spinner** shows extra detail on L2/L3 workloads
- **BMP growth**, **large output**, **near pixel limit**, and **RAM peak** messages unified in the rail
