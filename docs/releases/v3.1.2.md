# Camaleon v3.1.2 — Firefox Android offline fix

**Date:** 2026-06-11  
**Branch:** `dev` → `main`  
**Tag:** `v3.1.2`  
**Engine:** 1.6.0 (unchanged)

## Summary

Fixes **offline navigation on Firefox for Android** (and other Firefox builds affected by the same preload behavior). Chrome, Edge, Safari, and Firefox desktop were already working; mobile Firefox showed the browser’s native “no connection” page instead of Camaleon’s cached shell.

## Root cause

The Service Worker had `navigationPreload: true`. When offline:

- **Chrome / Safari:** `FetchEvent.preloadResponse` **rejects** → Serwist falls back to precache or `/~offline`.
- **Firefox:** `preloadResponse` **resolves** to a `Response` with `type: "error"` → that error is returned to the browser → native `NS_ERROR_OFFLINE` / “No se puede conectar” screen.

This is a known interoperability gap ([Mozilla #1802711](https://bugzilla.mozilla.org/show_bug.cgi?id=1802711), [Workbox #3134](https://github.com/GoogleChrome/workbox/issues/3134)).

Camaleon already **precaches HTML** for `/` and all 21 `/transmute/*` routes, so navigation preload adds little benefit and breaks Firefox offline.

## Fix

`frontend/src/app/sw.ts` — set `navigationPreload: false`.

No change to wasm caching, Settings S5 full toolkit download, or offline mode toggle.

## QA (validated)

1. Production or `preview:cf` / Wrangler tunnel (HTTPS required on mobile).
2. Visit online → Settings → download engines (optional) → **reload once**.
3. Airplane mode → open `/` or any `/transmute/*` route in **Firefox Android**.
4. **Expected:** Camaleon loads from cache (or `/~offline` if shell not yet precached).
5. **Regression:** Chrome Android and desktop browsers unchanged.

## User-facing note

If you tested offline on Firefox before this release, clear site data once or reload online so the updated Service Worker installs.
