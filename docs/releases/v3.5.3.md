# Camaleon v3.5.3 — Low-end device resilience & adaptive WASM loading

**Date:** 2026-06-22
**Branch:** `dev`
**Tag:** `v3.5.3`
**Engine:** 1.6.0 (unchanged)

## Summary

Device-aware resilience release: **adaptive WASM loading strategies** for low-end devices, **storage pressure detection**, and a **device score display** in Performance settings. Prevents the `wasm validation error: bad type` crash on resource-constrained devices (e.g. LG K50, 3 GB RAM, 1 GB free storage) by switching from streaming to buffered-with-retry WASM instantiation.

## Highlights

### Adaptive WASM loading strategy

- **Symptom:** On low-end devices with extreme memory/storage pressure, `WebAssembly.instantiateStreaming()` produces `"wasm validation error: at offset N: bad type"` — the WASM binary arrives truncated or corrupted during streaming.
- **Fix:** New `initWasmModule()` in `load-glue.ts` supports three strategies:
  - **`streaming`** (high/mid tier): original behavior — `module.default()` with `instantiateStreaming`.
  - **`buffered`** (mid tier fallback): pre-fetches complete `.wasm` ArrayBuffer, passes to `module.default(buffer)` — avoids streaming corruption.
  - **`buffered-with-retry`** (low tier): same as buffered, plus up to 2 retries with cache-bust URL on `wasm validation error`.
- Strategy selected automatically via `computeWasmLoadHints(tier)` in new `device-capability.ts` module.
- All 13 transmutator crates + frame-preview worker migrated to `initWasmModule()`.

### Storage pressure detection

- `navigator.storage.estimate()` queried client-side (zero telemetry) to detect browser storage pressure.
- <5% free → `critical` (penalizes device score by -20 pts).
- <15% free → `warning` (-10 pts).
- Integrated into `ResourceSignals.freeStoragePercent` and scored in `computeResourceProfile()`.

### New module: `lib/device/device-capability.ts`

- `computeWasmLoadHints(tier)` — derives `{ strategy, retries }` from device tier.
- `computeStoragePressure(freePercent)` — classifies storage health.
- `computeDeviceCapabilityProfile(resource, freePercent)` — full profile with WASM hints.
- `scoreRecommendationKey(tier)` — maps tier to i18n recommendation label.

### Worker protocol: `engineLoadHints`

- New optional field on `WorkerRequest` / `WorkerRequestMeta`: `engineLoadHints?: { strategy, retries }`.
- Propagated from `useFileMetrics` → `sendMessage` → worker, where `activeEngineHints` is set before module init.

### Device score in Performance settings (S3)

- When opening Settings → Performance, a **device score bar** (0-100, color-coded) is displayed with the auto-detected tier.
- **Adaptive recommendation message** explains *why* the auto-detected tier was chosen and what it means:
  - **Conservative** (score <35): low RAM, few cores, or critical storage.
  - **Balanced** (35-64): moderate resources.
  - **Aggressive** (≥65): plenty of headroom.
- All computation is local — no telemetry, no server calls.

### Privacy

All device signals are standard browser APIs read client-side only:
- `navigator.deviceMemory` (coarse GB)
- `navigator.hardwareConcurrency` (logical cores)
- `navigator.connection.effectiveType` / `saveData`
- `navigator.storage.estimate()` (quota/usage)
- **No data leaves the browser.** No new permissions required.
