## 3. Architectural Decisions

| Decision | Rationale | SPEC section affected |
|----------|-----------|----------------------|
| `MAX_INPUT_BYTES = 50 MB` | Matches typical browser memory budget; prevents main-thread OOM during Worker transfer. 50 MB covers high-resolution JPEGs (e.g. 6000×4000 at ~30 MB) with headroom. | §5.1 |
| `wasm-bindgen` errors thrown, not returned | `Result<T, String>` maps to `Uint8Array` return + throws on `Err`. Worker wraps call in `try-catch` rather than checking return type. | §5.2, §6.2 |
| Wasm artifacts gitignored | Generated artifacts are environment-dependent; build step documented in README. Avoids binary bloat in repo. | §6.3 |
| `/* webpackIgnore: true */` on Wasm import | Next.js webpack otherwise attempts to bundle `/wasm/` path; magic comment defers resolution to browser runtime. | §6.2 |
| Module worker (`type: "module"`) | Required for dynamic `import()` of ES module Wasm glue inside Worker context. | §6.2 |
| PowerShell script (not bash) for build | Host platform is Windows; `npm run build:wasm` provides cross-platform alternative via cargo-installed `wasm-pack`. | §8 |
