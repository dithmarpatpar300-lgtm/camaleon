## Summary

Ships the **Semantic Alpha Engine**: one policy for **meaningful** transparency (pixels with α &lt; 255) across all lossy-input tools. Fixes false `TransparencyNotice` on opaque RGBA TIFFs and aligns prepare-time UI with encode-time flatten.

## User-facing

- **PNG / WebP / GIF / BMP / TIFF → JPEG** — transparency banner and background picker only when alpha would visibly change the output
- **TIFF → JPEG** — opaque RGBA masters (e.g. large archival TIFFs) no longer show a false transparency warning
- **Resize revert** — alpha re-assessed when returning to the original file after astro downscale
- What's New entry **v1.11.0** (EN / ES)

## Technical

- `core_utils::semantic_alpha` — `AlphaAssessment`, probe downscale (512 px), sampled scan (8192 px), header gates
- Wasm: `assess_alpha` (BMP, PNG, WebP, GIF), `assess_page_alpha` (TIFF)
- Frontend: `lib/semantic-alpha/` router; `run-prepare.ts` + `TransmutationPanel` integration
- Encode: all flatten paths use `dynamic_image_has_meaningful_alpha`
- SPEC §5.5.3; fixtures under `docs/fixtures/semantic-alpha/`; per-crate contract tests
- `TiffMeta.pageHasAlpha` deprecated in TS (structural only)
