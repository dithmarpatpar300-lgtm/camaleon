# Camaleon v3.3.1 — Risk unlock UX & Settings deep-link

**Date:** 2026-06-19  
**Branch:** `dev`  
**Tag:** `v3.3.1`  
**Engine:** 1.6.0 (unchanged)

## Summary

Fixes the **Risk mode unlock loop**: when a file is blocked by standard byte limits, enabling Risk mode now offers a **Continue** confirmation with the **same file retained** — single-tool, Universal handoff, and batch. Adds **Settings deep-link focus** so limit hints scroll to the relevant section (Risk, Offline, Batch, etc.) with a tone-matched pulse.

## Changes

### Risk unlock proceed (limit pipeline UX)

- `risk-unlock.ts` — shared logic for when to prompt after Risk mode toggles on (`shouldPromptRiskUnlockProceed`, standard vs risk hard-limit helpers).
- `RiskUnlockProceedPanel.tsx` — confirmation UI (“Risk mode active — continue with loaded file?”) with **Continue** / **Start over**.
- `TransmutationPanel.tsx` — retains gate-blocked files in `hardLimitPendingFile`; re-prepares on Continue; staged workspace + consent/hard-file unblock paths.
- `StagedWorkspace.tsx` — blocks Transmutar until user confirms Risk unlock when applicable.
- `BatchTransmutationPanel.tsx` — re-queues `blocked` / `hard_file` rows after Continue; consent bypass when Risk enables.
- `risk-unlock.test.ts` — Vitest coverage for unlock prompt rules.
- i18n `panel.riskUnlock.*` (EN/ES).

### Settings focus (S1–S7 deep-link)

- `settings-focus.ts` — `openSettings({ focus })` targets (`risk`, `offline`, `batch`, `performance`, `notices`, `updates`, `defaults`); scroll + section pulse (warning/accent/muted tones).
- `SettingsProvider.tsx` — `focusRequest` queue consumed by drawer after open animation.
- `SettingsDrawer.tsx` / `SettingsSection.tsx` — `focusTarget`, `data-settings-focus-card` hooks.
- `LimitUnlockHint.tsx` — **Open Settings** deep-links to **Advanced / Risk** with focus pulse.
- `globals.css` — `settingsSectionFocusPulse` animation (reduced-motion → static highlight).

## QA exit gate

1. Drop a **>150 MB** PNG with Risk **off** → hard-limit error + unlock hint → open Settings via hint → enable Risk → **Risk unlock** panel with file name/size → **Continue** → prepare → transmute.
2. Same flow via **Universal transmutator** handoff (`?handoff=`).
3. **Batch:** one blocked `hard_file` row → enable Risk → Continue → row re-prepares to `ready`.
4. Staged file with Risk off (hard file block or elevated consent) → enable Risk → confirm in workspace → Transmutar enabled.
5. Disable Risk again → hard-limit error or `RiskDeactivatedNotice` restores as before.
6. `npm test` — 134 Vitest tests pass.
