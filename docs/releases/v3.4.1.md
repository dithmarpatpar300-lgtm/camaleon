# Camaleon v3.4.1 — Offline persistence fix

**Date:** 2026-06-20  
**Branch:** `dev` → `main`  
**Tag:** `v3.4.1`  
**Engine:** 1.6.0 (unchanged)

## Summary

Fixes PWA offline reliability after **clear cache**, **app update**, or **F5 without network**. Settings now reports **app shell** and **Wasm engines** as separate readiness layers. Offline Mode is gated until both are cached.

## Root causes fixed

1. **P0:** `applyAppUpdate()` purged active Serwist precache after activating the new service worker.
2. **P1:** `clearOfflineCaches()` wiped shell HTML/JS; S5 download only repopulated Wasm engines.
3. **P2:** UI showed 13/13 engines as “offline ready” without measuring shell coverage.
4. **P3:** Force-offline returned 503 before Serwist fallback (`/~offline`, precache pathname match).

## Changes

### Dual readiness (shell + Wasm)

- `shell-cache-status.ts` — measures home, `/~offline`, tool routes, static chunks.
- Settings: separate **App shell** and **Wasm engines** stats; **Offline readiness** bar = min(shell%, wasm%).
- Offline Mode blocked until `shellReady && wasmReady`.

### Recovery

- `reprecache-appShell()` — SW message `REPRECACHE_SHELL` + main-thread fallback.
- `clearOfflineCaches({ reprecacheShell })` — auto-repopulates shell when online.
- `ShellCacheBootstrap` — silent recovery on mount; session flag after app update.

### App update (P0)

- Removed post-activate `purgeAppShellCaches()`; Serwist `cleanupOutdatedCaches` handles stale buckets.
- `markShellReprecachePending()` before hard reload.

### Force-offline (P3)

- SW + `network-guard.ts`: cache match → `/~offline` for documents → pathname scan for assets → 503 last resort.

## QA exit gate

1. Clear cache → S5 → F5 offline on `/` and `/transmute/*` → app loads.
2. App update “Update now” → F5 offline → same (P0 regression).
3. Offline Mode ON with both layers ready → navigate + F5 → no 503/ChunkLoadError.
4. Offline Mode ON without shell → UI warns; Restore offline cache works.
5. Settings shows shell + Wasm separately; offline ready only when both OK.
6. `npm test` passes (160+).
