# Camaleon v3.5.4 — Offline mode chunk error fix & cache resilience

**Date:** 2026-06-22
**Branch:** `dev`
**Tag:** `v3.5.4`
**Engine:** 1.6.0 (unchanged)

## Summary

Resilience release fixing a critical **`ChunkLoadError` during force-offline navigation** and preventing **cache duplication** that caused progressive degradation of offline mode. Also adds proper **error boundaries** for chunk-load failures so users see a recovery UI instead of a blank page.

## Highlights

### ChunkLoadError boundary (P1)

- **Symptom:** Navigating between routes in force-offline mode eventually produced a blank page with `ChunkLoadError: Loading chunk N failed` and `503 (Offline Mode)` in console.
- **Root cause:** Next.js loads page chunks via dynamic `import()`, which bypasses `window.fetch` (patched by `network-guard.ts`) and goes directly through the Service Worker. When a chunk was missing from cache, the SW returned 503, and Next.js had no error boundary to handle it.
- **Fix:** Added `app/error.tsx` and `app/global-error.tsx` error boundaries that detect `ChunkLoadError` / `Loading chunk` / `Failed to fetch` and show a user-friendly recovery UI with "Try again" and "Go home" buttons.

### Cache duplication prevention (P2)

- **Symptom:** `SHELL_CACHE_NAME` grew unboundedly because every normal-mode navigation added duplicate entries for resources already cached by Serwist's precache.
- **Fix:** New `isAlreadyCachedInSw()` function checks if a request URL already exists in any cache bucket before calling `cache.put()` in both `serveOfflineShellAssetRequest` and `shellDocumentRuntimeCache`.

### Better offline fallback (P3)

- Enhanced `tryForceOfflineFallbackInSw()` to try pathname matching with stripped query params for chunk URLs.
- Force-offline listener now serves `/~offline` or `/` for document requests before returning 503, giving users a navigable page instead of a raw error.

### Cache entry limit (P4)

- New `trimShellCache()` function caps `SHELL_CACHE_NAME` at **75 entries**, removing oldest entries first.
- Called after each new `cache.put()` and on SW `activate` event.
- Prevents unbounded growth that caused the browser to evict entries and trigger chunk-load failures.
